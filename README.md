# Каталог книг

Фронтенд для API каталога книг (Yii2 + MySQL) по спецификации `book.yaml`.

Бэкенда под рукой не было, поэтому в проект добавлен мок-сервер на MSW — он повторяет
все эндпоинты спеки, включая коды ошибок и задержки. Приложение запускается и кликается
как есть.

## Запуск

```bash
npm install
npm run dev
```

Открыть http://localhost:5173, логин **admin / admin**.

```bash
npm run build      # vue-tsc + сборка
npm run preview
node verify.mjs    # e2e-проверки в Chromium, нужен запущенный preview
```

## Подключение реального бэкенда

Через `.env` (образец — `.env.example`), код менять не нужно:

```env
VITE_ENABLE_MOCKS=false
VITE_API_BASE_URL=/api/v1
VITE_API_PROXY_TARGET=http://localhost:8080
```

Последняя переменная включает прокси в `vite.config.ts`, чтобы в разработке не ловить
CORS. В продакшене этим занимается nginx.

## Стек

Vue 3 (`<script setup>`) + TypeScript + Vite, Vue Router, Pinia, TanStack Vue Query,
VeeValidate + Zod, MSW для моков.

Pinia держит только клиентское состояние — сессию и уведомления. Данные с бэкенда
в стор не кладу: кэш, инвалидация и отмена запросов уже есть в Vue Query, а два
источника правды на одни и те же данные быстро расходятся.

UI-кит не подключал: компонентов немного, а задание как раз про вёрстку.

## Структура

```
src/
  app/        роутер, layout, queryClient
  pages/      экраны
  features/   auth, books, authors, subscription, report
  shared/     api-слой, ui-компоненты, хелперы
  stores/     Pinia
  mocks/      мок-бэкенд
```

`shared/api` и `mocks` не зависят от Vue — это обычный TypeScript.

## Что стоит отметить по спеке

**PUT и PATCH для книги.** `PUT /books/{id}` принимает multipart и требует `cover`,
а в схеме `PATCH` поля обложки нет вообще. Значит поправить название книги, не
перезаливая картинку, можно только через PATCH. Метод выбирается по тому, выбрал ли
пользователь новый файл (`features/books/queries.ts`).

**`per-page` в запросе, `per_page` в ответе.** Не опечатка, а стиль Yii2.

**Ошибки 422** раскладываются по полям формы через `setFieldError`, а не показываются
общим сообщением. Уникальность ISBN и существование `author_id` знает только бэкенд,
и его ответ должен оказаться под нужным полем.

**Фильтры каталога живут в URL.** Ссылку можно отправить, «назад» возвращает прошлый
фильтр, F5 ничего не сбрасывает. Плюс Vue Query кэширует выдачу по тем же параметрам.

**Права** проверяются навигационным гардом (`meta.requiresAuth`) — он срабатывает до
монтирования страницы, поэтому защищённый экран не мигает перед редиректом. Это UX;
настоящая проверка прав на бэкенде.

## Подписка на новинки

В `book.yaml` этого эндпоинта нет, хотя в ТЗ он есть. Контракт придумал сам, он помечен
в `shared/api/types.ts` и реализован в моках:

```
POST /api/v1/authors/{id}/subscriptions   { "phone": "+79991234567" }
```

Телефон нормализую к E.164 на клиенте: вводят по-разному, на бэкенд должен уходить
один формат.

Саму отправку SMS через smspilot на фронте не делал. Ключ из браузерного бандла
достаётся в два клика, плюс CORS, плюс событие «вышла новая книга» возникает на
сервере, когда вкладка может быть закрыта. Это работа бэкенда: при создании книги
взять подписчиков её авторов и поставить задачу на рассылку.

## Чего не сделал

- Тестов нет. В первую очередь я бы покрыл `isValidIsbn`, `normalizePhone` и `buildQuery` —
  чистые функции, дешёвые в тестировании. Вместо unit-тестов пока `verify.mjs`:
  17 сценариев в реальном браузере (`node verify.mjs` при запущенном preview).
- Типы из OpenAPI перенёс руками. На живом проекте их надо генерировать
  (`openapi-typescript`), чтобы расхождение со спекой ломало сборку.
- Фильтр по автору API умеет (`author_id`), в интерфейс не вынес — работает только
  через URL.
- Оптимистичных обновлений нет, после мутаций просто инвалидирую кэш.

## Про мок-режим

Мок-«база» живёт в памяти вкладки, поэтому перезагрузка страницы возвращает исходные
данные, а загруженные обложки (они хранятся как object URL) пропадают. С реальным
бэкендом этого нет.

Токен храню в localStorage: спека отдаёт его телом ответа, а не httpOnly-кукой,
и `/auth/me` тоже нет, так что после перезагрузки сессию восстановить больше неоткуда.
Если бэкенд перейдёт на куку, `features/auth/tokenStorage.ts` просто удаляется.
